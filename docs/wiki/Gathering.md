# 最基础的聚气

本页说明聚气、炼化、肺经入账与全身自然储存；已实现的专用开脉入口与连续吐纳条件见[修炼与开脉](Cultivation.md)。

独立 UI Addon 现已提供手动吸呼的吐纳窗口。框架 `GatheringSession` 负责可信气流、摄入、炼化、发运与到达，Human 提供人体构型、呼吸能力和五行配方。Fabric 宿主已将同一流程绑定到真实玩家、主世界共享灵气区域及世界存档，接入方式见[宿主集成](Integration.md)。标题界面开发演示仍使用隔离内存宿主。

实际玩家需右键使用《炁脉札记》和聚气残卷，无须看完；Progression 在服务端立即记入对应身体进度，Human 在身体入口拒绝未解锁请求。札记只解锁修炼页，不能替代聚气卷；中焦卷独立授权中焦。普通肺加工能力仍是人体内容，残卷门槛放在玩家主动操作宿主。

## 自动吐纳

吐纳窗口可勾选“自动吐纳”，服务器在空气满/空边界交替吸呼，以固定前方气流引导真实粒子；只有真实口鼻接触才执行摄入。自动使用现有双肺容量与气流，耐力费用映射到现有 `diaphragm`（膈肌）账户，沿用30W；不消耗、不占用 `attention_network`。没有新增平行肺耐力账本。

`HumanBreathingNumbers` 集中占位 `AUTOMATIC_MIN_STAMINA_RATIO=0.8`、`AUTOMATIC_CAPTURE_EFFICIENCY=0.5`。有效膈肌耐力低于80%停止，释放占用，不自动重启。相同接触的环境采样体积为手动的一半，炼化仍为20%，摄入证据只记录实际扣取原料。停止后正常恢复；关窗、断线和实际移动结束会话。开脉及外壁动员自己的精力费用保持独立。

## 呼吸能力

`HumanContent.breathing()` 返回框架生成的 `BreathingProfile`，同时导出至服务端 JAR 的 `META-INF/kizuna_meridian/human-breathing.pb`，其他语言宿主可直接读取并装配。

| 项目 | 初始游戏值 |
|---|---|
| 呼吸器官 | `left_lung`、`right_lung` |
| 空气容量 | 每肺 2.5 L，总计 5 L |
| 空气流速 | 每肺 0.625 L/s，总计 1.25 L/s；满吸或全呼约 4 s |
| 呼吸组织 / 主动功率 | `diaphragm` / 30 W |
| 注意组织 / 主动功率 | `attention_network` / 4 W |
| 注意组织预算 | 300 J、爆发 1000 W、疲劳容量 100；代表玩家精力 |
| 手动配方 | `human:breath_metal/wood/water/fire/earth`，接触摄入采用 20% 转换比例 |
| 粒子采样体积 | `particle_volume_blocks = 1`；每颗原始量为当前浓度 × 1 格 |

以上为玩法初值。注意组织归属头部，是独立组织，不写入经脉或肺容量。有效呼吸耐力与精力从框架真实伤势和疲劳派生，综合条取较低比例；任一耗尽停止。正常配置精力在不恢复时约支持 75 s 的有效吸呼，停气和满/空边界不继续消耗。

呼吸配置通过 `body_action` 绑定 `human:breathing / 1`，框架在有效吸呼时启动占用，停气、肺满、排空、结束与关闭时解除本会话占用。膈肌疲劳半衰期 30 模拟秒，注意组织 20 秒；未被其他动作使用时按指数恢复，余力继续来自同一身体疲劳。关窗重开不会清除疲劳，重新开始会结清实际空闲时间。动作启停不重复收取已有吸呼费用。

五行输入统一炼化成 20% 无属性真元。吸气时靠近口鼻的每颗粒子都可触发接触摄入，同一事件不限一颗，运动轨迹穿过口鼻也可接收。当前浓度为 1 元/格时，一颗摄入约 1 元原料，得到 0.2 元无属性真元；浓度为 0.5 元/格时产出约 0.1 元。实际剂量受同属性库存与器官缓存空间约束，暂不按肺摄入速度或经过时间缩放。

接触时按目录配方比例即时转换，80% 损耗原子回到所选环境来源，20% 进入肺缓存，再沿既有肺出口与全身经脉运输。下一颗不用等待前一颗到货。空气和组织疲劳仍按有效吸呼结算，同段多颗只支付一次呼吸费用。原有固定 1 元配方与 0.05 元小配方保留给显式固定批次调用，其时长和剂量不再限制手动接触摄入。下方固定批次流程对应这些显式调用。

```text
区域真实灵气库存
    ↓ IntakeQi（原始五行游离态）
同侧肺缓存
    ↓ StartOrganRecipe（固定剂量与时长）
加工原料账户 → 20% 无属性游离态回到肺缓存
             → 80% 无属性游离态进入环境释放账
    ↓ TransportQi（对应肺 → 同侧肺经）
在途唯一货物
    ↓ AdvanceTime（可信到达事件）
肺经内腔
    ↓ 被动通路（扣源 → 在途 → 下游入账，按事件继续）
全身经脉自然储存；开拓状态仍为 UNOPENED
```

肺经接收产物后，已自动沿身体连接向全身经脉自然扩散，未开脉也能被动接收与流动。玩家无需逐条分配即可积累全身储量；连接速率与限制见[全身自然扩散与开脉要求](Cultivation.md)。

游炁八脉间形成[中焦周天](Human-Definition.md#中焦周天)：左肺产物先经左大肠进入右胃，右肺产物经右大肠进入左胃；各侧脾经既可回肺，也保留到心经的主干。输送仍按局部容量占比差执行，环是可达通路，不保证每一批货物强制转满一圈。

## 固定小批次

`human:lung_refine_metal/wood/water/fire/earth` 五条原始配方分别消耗 1 元对应属性的游离态灵气，耗时 1000 模拟毫秒，输出 0.2 元无属性游离态真元，最低游炁。两肺都使用 `human:lung` 类型，也可运行上述手动小批配方。

使用单属性小批次，不要求区域凑齐特定五行配比。混合摄入也会原样保存在肺中，可按库存逐条运行对应配方；同一肺每次只加工一批。不足 1 元的零头保留在缓存，继续摄入后才达到固定配方剂量。无属性环境真元、其他模组属性和高阶相态目前没有人体默认炼化配方。

五行配方初始均为 20%，沿用此前规划建议。尚未接入器官实例改造后的动态效率。环境木气多只影响可取得的输入，不赋予游炁角色木属性攻击。

肺炼化属于人体固有生理内容，不要求先读功法书；后续功法包可依赖 `human` 并使用同一器官类型配置新的受约束配方。

## 实际操作与时间

`GatheringRequests` 是操作端请求构造器，不是自动运行器：

1. 取得有权读取的最新身体与内容配方，选择肺、输入属性和剂量。
2. 积累足够可信活动时间后提交 `intake`。来源由宿主确认，环境库存、浓度供给与肺摄入速度共同限流。
3. 刷新快照，提交 `refine`。请求只传配方 ID/版本，产物、效率和时长由权威目录解析。
4. 宿主等到加工事件，提交 `settle`，取得真实产物；未来输出不提前入账。
5. 刷新快照，提交 `store`，指定实际连接和吞吐。真元先从肺缓存扣除，转入唯一在途账户。
6. 宿主等到对应肺发运批次的到达事件，再 `settle`，肺经入账，并自动启动可执行的被动批次。
7. 后续运输到达继续触发自然扩散；平衡后不周期计算。此过程不开放意念主动取用。

事件由宿主可信时间推进，没有逐帧算账。演示只跳到事件时刻，不代表游戏中可以由玩家快进。命令成功后使用新 revision；网络重试重发同一请求 ID 和内容，不能生成新 ID 重新领取已经消费的时间。

常见失败直接保留框架码：`ENVIRONMENT_BUDGET_EXCEEDED` 表示共享供给不足；`MODULE_UNAVAILABLE` 表示肺或胸部失能；`CAPACITY_EXCEEDED` 表示缓存或目标空间不足；`TIME_REQUIRES_SETTLEMENT` 表示需先结算可信时间；`REVISION_CONFLICT` 表示需刷新快照。单步失败不写账，已经完成的其他步骤保留实际结果。

## 演示数值

运行 `./gradlew demo`，演示环境 100 元木气 / 100 格，供给 1 元/秒；使用左肺：

| 事件 | 原区域库存 | 肺缓存与加工 | 新炼化产物 | 环境释放账 |
|---|---|---|---|---|
| 出生 | 100 | 0 | 尚未产生；全身初始内腔共 0.36 元 | 0 |
| 摄入 | 99 | 1 | 尚未产生 | 0 |
| 炼化完成 | 99 | 0.2 | 保留在肺 | 0.8 |
| 发运 | 99 | 0 | 0.2 元进入对应肺运输批次 | 0.8 |
| 到达肺经 | 99 | 0 | 沿全身通路自然扩散，余额与在途共同持有 | 0.8 |
| 120 s 结算 | 99 | 0 | 全身内腔共 0.56 元，36 条均高于出生余额，无在途 | 0.8 |

肺出口运输距离 0.1 米，按框架 `距离/速度 + 元数/吞吐` 计算时间。自然扩散与肺出口共享经脉吞吐，演示和持续编排读取剩余额度，无额度时等真实到达释放预约。本轮新拓扑中，炼化完成时肺出口可用速率为 0.5 元/秒，0.2 元批次用时 0.5 秒；不能再固定申请全部 1 元/秒或假定 0.3 秒到达。出生各脉容量不同，也会触发少量初始平衡流动，因此演示按连接 ID 查找肺发运批次，不假定在途列表第一项就是该批次。整轮身体与环境合计始终为 100.36 元。

### 连接变更后的分布对照

固定实验使用新生身体全部 36 条经脉：1 秒时左肺摄入 1 元木气，2 秒完成炼化，左右两种拓扑均以 **0.25 元/秒**发运同一份 0.2 元产物，2.9 秒到达肺经；分别结算至 3、5、10、30、120 秒。旧拓扑为左右各自循环且无脾→肺，新拓扑仅替换两条大肠→胃并增加两条回流。固定相同发运速率是为了隔离连接变化，不代表演示或手动吐纳强制使用该速率。

| 5 秒时内腔余额（元） | 旧拓扑 | 中焦周天 | 变化 |
|---|---:|---:|---:|
| 左肺 | 0.016476 | 0.015822 | −0.000653 |
| 左大肠 | 0.037978 | 0.037063 | −0.000915 |
| 左胃 | 0.036805 | 0.009234 | −0.027571 |
| 左脾 | 0.025820 | 0.009234 | −0.016586 |
| 右肺 | 0.011986 | 0.013248 | +0.001261 |
| 右大肠 | 0.009855 | 0.009351 | −0.000504 |
| 右胃 | 0.009718 | 0.030423 | +0.020705 |
| 右脾 | 0.009718 | 0.015196 | +0.005478 |
| 全身在途 | 0.027725 | 0.042422 | +0.014697 |

早期新增储量明显转向对侧胃、脾；在途增加来自路线与共享吞吐变化。120 秒时两者都没有在途，36 条均高于出生余额：八脉内腔合计由 0.113320 元变为 0.112040 元（−0.001280 元），其余经脉增加同量。全身两份最终分布的绝对差之和除二为 0.008495 元，约占 0.56 元总量的 1.52%。这表示重新分布，不是资源损耗；两者身体均为 0.56 元、原区域 99 元、环境释放账 0.8 元。最小批次阈值允许静止后的微小压差，不能据此要求全身严格平均。

上述对照由一次性测量验证后移除探针；长期回归保留八脉独立成环与逐边真实扩散、24 条正经主环、五行双肺摄入与守恒、存档恢复，以及游戏服务端玩家宿主验证。

普通加工完成时，框架把损耗记入 `environmentQi()` 默认环境释放账。它已经离开身体，但尚未按坐标归入原区域，演示不能把它再加回原区域而仍保留默认账。真实宿主按位置归属和区域扩散接入后才能完成区域回收；这里明确展示两份互不重叠的环境账户。

## 保存与限制

宿主保存实际身体、来源库存与使用预算、命令回执和环境释放账。恢复不重新调用人体出生候选或区域初始化。已启动加工保存完整配方，运输保存唯一货物，断线后按框架事件规则继续。

本包的 `GatheringRequests` 保留逐步操作能力；手动吐纳、单轮编排、环境预览和 UI 归各自框架。开脉须另行启动规则，单独产物入脉不改变境界或开拓进度。自然扩散腾出肺经局部空间后可以继续吐纳；全身满载、局部入向预约或通路失能仍限制摄入/发运，失败不丢弃肺内已加工产物。

全身被动储元与[开脉运行](Cultivation.md)共用同一肺加工、组织费用、通路和真元账本。活动开脉时专用引导接管经脉间扩散方向；吐纳选项读取扣除在途预约后的稳定体积余量，持续摄入和开脉费用共同结算。

人体展示资源声明 `meditate` 动画、`head` 气流入口挂点和 `chest` 肺挂点。UI 直接使用必装动画侧播放器；Human 宿主按权威吐纳状态直接调用 Animations 服务端播放／停止接口，使用动画模组自己的 Protobuf 转发。缺接线或资源明确报错，详见[宿主集成](Integration.md)。
