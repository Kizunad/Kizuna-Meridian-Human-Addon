# 人体模型与空间位置

模型、贴图、经脉位置及身体引用全部归 Human，UI 不维护人体坐标表。本包不依赖 UI 或 Inventory UI。五层使用同一个 Blockbench 拼装模型：原版玩家比例表层、骨架、肌肉、器官和金色血管式经脉。

## 内容

| 层 | 当前内容 | 绑定 |
|---|---|---|
| `surface` | 原版玩家静止外形，使用当前玩家基础皮肤，支持宽臂与窄臂，17 个连续选择区域；默认只显示此层 | 独立皮肤组织 ID |
| `skeleton` | 23 个骨骼组：颅骨、下颌、分节脊柱、胸骨、左右肋骨/肩带、骨盆、四肢骨及手足骨 | 独立 `bone_` 组织 ID |
| `muscles` | 19 块具名肌肉，阶梯肌腹、表面肌束、收窄附着端及左右镜像 | 组织 ID |
| `organs` | 15 个器官：脑、左右眼、左右肺、心、肝胆胃脾肾、膀胱、小肠与大肠 | 器官 ID |
| `meridians` | 36 条金色血管式脉络；各有弯曲主干、渐细分支、交织深度和局部管径起伏 | 经脉 ID |

解剖模型的几何与贴图编辑源为 `client/src/model/human.bbmodel`，身体映射与说明存放于 `human.textproto`，使用框架 `BodyPresentation` 的标准 Protobuf 文本格式。`BlockbenchModel` 在构建期导出解剖网格与图集；`PlayerSkinSurface` 根据体表选区范围生成原版 64×64 皮肤 UV 与同拓扑窄臂变体，再写入通用 `player_skin` 声明。运行时 `HumanPresentation.create()` 只读取构建产物，不生成坐标。产物为 `assets/meridian_human/meridian/adult.pb` 和 `assets/meridian_human/textures/body/anatomy.png`，模型资源 ID 为 `meridian_human:meridian/adult.pb`，精确绑定 `human:adult` 修订 1。

## 拼装与编辑

在 Blockbench 打开 `human.bbmodel`，格式为原生自由模型。`assembly.human` 下按 `anchor.*` 部位枢轴组织骨架、肌肉和器官；头附于颈、颈附于胸，四肢按近端到远端连接。各层共享同一个父部位与坐标系，调整父组时其内部组织随之变换。经脉网位于整体身体下的 `routes.meridians`，覆盖多个部位；单条脉络保持自身完整主干与分支。

骨骼先占据支撑空间，器官装入保留的腔隙，肌肉贴合骨骼外侧；重叠的实体交界已裁切并留有约 0.012 模型像素的间隙。该裁切已写入编辑源，不在游戏内计算。经脉作为组织内通路穿行，表层作为包围外形，这两者并不按互斥实体处理。正常内外遮挡保留，取消勾选外层即可查看内部。

各可选组名（如 `organs.left_eye`）与 `human.textproto` 的 `visuals.id` 一致。保留组名即可自由调整内部方块和网格；新增身体对象时同时增加权威定义和映射。构建器支持方块面 UV、三角面、凸四边面、元素及父组枢轴旋转，导出时烘焙为米制坐标。动画、Box UV、多个图集等编辑特性不属于当前导入子集。

模型内嵌一张 256×320 原创图集，包含骨质孔隙、纵向肌束、脑沟回、肺表面、内脏组织、眼白虹膜、灰色表层与金色经脉材质。直接在 Blockbench 绘制并保存即可参与构建；导出的 PNG 是构建产物，不是第二份编辑源。骨架、肌肉、器官和经脉共用图集，UV 接缝顶点独立，其他重复顶点合并。图集和网格只影响展示，不改变血量与器官能力。

坐标为局部米，Y 向上、Z 向前，X 正向为人体自身左侧。体表采用原版玩家基础几何：头 8×8×8、躯干 8×12×4、宽臂与腿 4×12×4 模型像素，每像素 1/16 米，展示高度为 2 米（不是碰撞箱高度）。窄臂宽 3 像素，肩位置沿原版模型下移半像素。UI 使用当前本地玩家基础皮肤；没有玩家时回退到原版 Steve 资源。17 个命中区域分别绑定对应的 `_skin` 组织，显示独立皮肤 HP。使用中立站姿，目前不叠加皮肤的帽子、外套和袖套第二层，也不展示装备；吐纳与经脉场景继续使用黑色剪影。

骨架沿该外形布置：眼眶和鼻孔为几何凹槽，颅腔、胸廓和骨盆保留空腔；前臂及小腿为双骨，手足分出指趾轮廓。23 个骨骼组可分别选择和聚焦，信息显示各自 `bone_` 组织的独立 HP。整体包围盒各层固定；肌肉前后位置区分，左右器官分别绑定各自实例。经脉路径为现有简化连接设计的示意，不能用于医学或推导真元运输距离。

肌肉层沿用玩家方块风格。胸大肌从胸骨侧向上臂收成扇形；肱二头肌在上臂前侧，肱三头肌在后侧；肱桡肌向腕部收窄，拇对掌肌位于掌侧；臀大肌铺在骨盆后方，股直肌沿大腿前方延伸，腓肠肌分出内外两头；趾短屈肌贴足底并分为四束，膈肌形成横隔胸腹的双穹顶。表面浅槽下保留连续肌腹，各肌群使用不同深浅的红褐色。所有肌束与附着端都属于原有的同一个组织节点，选择后统一高亮和显示权威组织数据。

本轮细化现有 19 块组织，不等于完整人体肌肉目录。头颈、肩部、腹壁和背部等尚未登记肌肉的区域仍留空，后续扩充时应先增加对应身体组织，再提供几何。

器官层全部使用与骨架、肌肉一致的方块几何。脑分左右半球、表面沟回、小脑和脑干轮廓；肺有收窄的肺尖和分叶浅沟，左肺留心切迹；心脏前置，心尖朝左下，并附带短血管与主动脉弓外观。肝脏右叶宽厚、左叶较薄，胆囊呈细颈囊形位于其下方；胃呈 J 形，脾窄长且位于胃外侧偏后；双肾位于腹腔后方，保留朝内的肾门凹口，右肾略低；膀胱位于盆腔前方。大肠围住连续盘曲的小肠，结肠袋和乙状弯折提供形状辨识。

分叶、血管、脑干及肠道末端只是相应器官网格的一部分，不增加独立状态。左右眼嵌入已有眼眶，每眼包含眼白与虹膜/瞳孔表面，分别绑定 `left_eye`、`right_eye`，每眼 4 HP。当前 15 个器官是游戏化布局，并非完整解剖模型。点击读取该器官自己的 HP、吞吐、缓存和加工状态；背侧器官聚焦沿用通用相机规则。

经脉采用金色血管风格，与方块组织形成材质和形态区别。十二正经各有独立主干和两条局部分支：手三阴分布在掌侧不同位置，手三阳绕向手背和臂后；足三阴沿内侧前后分布，胃经偏前、胆经偏外、膀胱经偏后。左右实例使用镜像布局。阴阳跷脉由踝部上行，阴阳维脉分别绕胸腹前后；任督位于前后中轴，冲脉深居躯干，带脉围腰闭合。这里仍按现有模块覆盖范围作游戏化布置，未声称完整中医经脉路径。

每条脉络按自身控制点生成连续曲线，主干存在粗细起伏，分支向末端收尖。前后深度交错使线路有缠绕感；任督冲带较粗、四肢正经次之、细支更窄。环形带脉闭合接缝，主干和分支合在同一个可选对象中，选中时整条高亮、其他对象调暗。金色深浅只区分外观，不表示五行、开拓成功或正在运转。视觉分叉不新增身体模块、端口或运输连接，仍从唯一经脉状态读取储量、容量、损伤和开拓进度。

曲线管壁已提取为 Blockbench 原生网格，客户端只读取静态 Protobuf；几何粗细不参与吞吐或阻力计算。

所有节点都可独立选中，展示绑定引用权威身体已有的部位、组织、器官或经脉状态。皮肤和骨组由 `HumanAnatomy` 声明，模型不自行生成状态。`human.textproto` 中的表层、骨架布局保留部位元数据，构建期由导出器绑定为 `_skin`、`bone_` 组织；调整几何不改变账本。旧构型缺少骨组时须显式迁移，不能由渲染层伪造满血。身体基础数值见[人体定义](Human-Definition.md)。

## 构建与查看

运行 `./gradlew build` 即导出模型并随 JAR 打包。整体测试读取实际 JAR，校验模型和当前身体定义的映射、肌肉/器官/经脉覆盖以及网格索引。构建期导出代码不进入分发 JAR。

在独立 `Kizuna-Meridian-UI-Addon` 仓库运行：

```bash
./gradlew -PhumanAddonDir="../Kizuna-Meridian-Human-Addon" :client:runDemo
```

UI 负责分层绘制、鼠标选取、镜头聚焦和状态面板。人体数据仅在演示装配中被选用，其他生物可用相同契约提供自己的模型。正式宿主仍需绑定实际身体快照；本资源容器不会自行创建玩家身体或启动聚气。

UI 的游戏内 smoke 与 Minecraft 烘焙出的宽臂玩家六组几何核对外形范围，并验收骨架、肌肉、15 个器官和 36 条经脉的聚焦、真实点击及状态信息。另验证左侧多层勾选、空显示组合、隐藏选中层以及骨架中眼球的实际点击，保存拼装全景和眼眶局部截图。Windows 原生演示使用同一份 Human 模型和贴图资源。
