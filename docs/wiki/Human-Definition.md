# 人体定义与初值

这些数值是基础内容的首轮游戏配置，不是生理测量结果，也不是主框架的默认值。定义位于 `server/src/main/java/dev/kizuna/meridian/human/server/HumanAnatomy.java`，全局身份、肺配方位于 `HumanContent.java`，出生规则位于 `HumanBirth.java`。

## 独立模块

### 公开模块标签

`human:adult` 通过 Framework 的模块 `tags` 声明功法绑定词汇：

| 标签 | 命中模块 |
|---|---|
| `human:hand_meridian` | 肺、大肠、心、小肠、心包、三焦经的左右实例 |
| `human:foot_meridian` | 胃、脾、肾、膀胱、胆、肝经的左右实例 |
| `human:layer_wandering_qi` | 与 `HumanOpening.minimumRealm` 一致的游炁层：左右肺、大肠、脾、胃经 |
| `human:arm_muscle` | 左右肱二头肌、肱三头肌、肱桡肌 |
| `human:leg_muscle` | 左右股直肌、腓肠肌、臀大肌 |
| `human:breathing` | 膈肌、左右肺 |

奇经不标手经或足经，只参与其境界的层标签；目前不增加后续境界层标签。
标签名是 Human 的公开内容契约，改名必须同步基础功法。绑定按模块种类再筛选标签，
因此 `human:breathing` 可同时用于组织与器官。玩家宿主接线见[玩家功法宿主](Technique-Host.md)。
既有身体继续使用保存的实际构型，不自动套用新模板标签。当前 Framework 没有受校验的构型标签迁移入口，
不能在 Human 解码存档时直接覆盖标签来绕过权威校验；无标签旧身体暂时无法绑定依赖标签的功法。
所需通用迁移能力：以模块种类和实际 ID 对照期望标签，仅为空集合补标签；已有非空集合与期望不同则拒绝。
迁移须保留其余实际构型、资源、伤势、时间及历史回执，经 Framework 校验后递增 revision，并由 Human 标脏保存。
具备该入口后，Human 才能按自己的模板提交迁移，并验证旧档加载、保存重载和功法施放完整流程。

| 肌肉 | 19 块：左右胸大肌、肱二头肌、肱三头肌、肱桡肌、拇对掌肌、臀大肌、股直肌、腓肠肌、趾短屈肌，以及膈肌 |
| 皮肤 | 每部位一个独立皮肤模块，共 17 个 |
| 骨骼 | 23 个独立骨组，以 `human:bone` 组织类型声明 |
| 注意组织 | 头部 `attention_network`，用于手动引导的精力做功预算 |
| 器官 | 15 个：脑、左右眼、左右肺、心、肝、胆、脾、胃、小肠、大肠、左右肾、膀胱 |
| 经脉 | 十二正经各左右实例共 24 条，任督冲带各一条，阴阳跷和阴阳维各左右实例共 8 条；总计 36 条 |

这是用于起步的代表性组织集合，合计 60 个组织：19 块肌肉、17 份皮肤、23 个骨组和 1 个注意组织，尚未枚举全部人体肌肉、骨骼、肌腱或关节。具名组织、器官与经脉独立声明，通过部位 ID 关联，不把肌肉基础能力写进经脉。

正经主干通过大肠经跨侧交接，左右十二正经合为一个 24 条的有向主环；每侧另有脾经回肺的单向支路。奇经用双向连接交汇，任督连接提供中轴左右可达性。该图是中医经脉布局灵感下的游戏简化，不宣称完整解剖路径或医疗意义。端口只有输入、输出两个，运行仍服从框架连接、吞吐和在途预约规则。

实际聚气连接为 `left_lung.to.meridian`、`right_lung.to.meridian`，分别从对应肺的输出到同侧肺经输入。其他器官目前只有定义和端口，肌肉只有基础能力；它们的供元支路、专属配方和输出玩法后续补齐。

### 中焦周天

游炁开放的八条已有经脉可独立组成一个 8 字形有向闭环，命名为 **中焦周天**：

```text
左肺 → 左大肠 → 右胃 → 右脾 → 右肺 → 右大肠 → 左胃 → 左脾 → 左肺
```

大肠经交接到对侧胃经，取意手阳明大肠经“交人中，左之右，右之左”；同侧脾经回肺取意手太阴肺经“起于中焦”。四条变更线路均为单向，距离沿用 0.3 米，阻力 0，被动吞吐 0.5 元/秒、最大批次 0.25 元、最小批次 0.0001 元，与其他正经间连接一致。没有新增经脉，仍为 36 条，总连接由 60 增为 62。

原有脾→心主干保留，所以完整构型包含回流分支，并非全图只有一个环。十二正经全部开放后，沿脾→心主干行进会经过左右共 24 条正经，再回到起点。只使用上述八脉也能通过脾→肺回流闭合，不依赖更高境界经脉。自然扩散沿相同权威连接运行；未解锁经脉参与被动流动的规则不变。

**“小周天”一词留给后续任督环**，不作为本八脉环的别名。当前已有任督交汇不代表该修炼玩法已经实现。

新连接用于新建身体。旧存档不迁移；已保存身体持有自己的 `structure`，更新模板、重登或改变客户端模型不会改写其连接。

| 任督冲带容量 | 内腔、外壁各 100 体积 |
| 经脉初始真元 | 每条内腔 0.01 元无属性游离态，共 0.36 元；外壁为零 |
| 经脉状态 | 完好，疲劳零，`UNOPENED / 0` |
| 经脉吞吐 / 承受度 / 疲劳容量 | 1 元/秒 / 1 / 100 |
| 肺缓存 / 单肺摄入 / 端口吞吐 | 200 体积（ρ=0.01 时 2 元）/ 1 元每秒 / 1 元每秒 |
| 其他器官缓存 / 吞吐 | 100 体积（ρ=0.01 时 1 元）/ 1 元每秒；不声明环境摄入 |

以上容量按液态参照体积配置，实际可容纳元数随真元密度变化；出生游离态真元以 `ρ = 0.01` 计算。出生真元由可信宿主在首次创建身体时一次初始化，不来自每次加载或登录。已有身体不得重新调用出生函数。器官缓存用于加工，不计入经脉体积或境界基准密度。

### 部位 HP

| 部位 | 最大 HP（左右各自） |
|---|---|
| 头 / 颈 / 胸 / 腹 / 骨盆 | 20 / 10 / 40 / 30 / 30 |
| 上臂 / 前臂 / 手 | 15 / 12 / 8 |
| 大腿 / 小腿 / 足 | 25 / 18 / 10 |

每块肌肉 HP 为 10、疲劳容量 100；皮肤 HP 为归属部位的 25%，主动能力为零。骨组 ID 以 `bone_` 开头，首版最大 HP 沿用所属部位的最大 HP，疲劳容量为 100，主动能力为零。皮肤、骨骼、肌肉、器官及部位分别持有 HP，框架不隐式联动这些账户；人体伤害策略可显式提交同一部位的多个目标损失。治疗仍只恢复指定账户。

`HumanDamage` 通过框架伤害接口计算处理结果。总体 HP 只汇总部位，不叠加组织或器官；伤害后总部位 HP 严格低于上限总和的 20%，或头部 HP 为零时判定死亡。器官 HP 为零先表示该器官失能。判死结果交给框架原子保存并释放全部真元，Human 不另存健康账本。Minecraft 原版伤害事件、部位护甲与实体死亡由独立 Vanilla Damage Addon 接线，见[宿主接入](Integration.md)。

新身体由出生函数初始化独立骨组。旧存档不迁移；既有存档缺少这些组织时不自动补骨、重生或补满 HP，模型资源更新也不生成身体状态。

左右眼分别是 `left_eye` / `right_eye`，归属头部，每眼最大 HP 为 4，出生时各自满血。采用其他普通器官相同的 100 体积缓存（密度 `0.01` 时等效 1 元）、1 元/秒吞吐及独立端口；当前没有视觉加工配方或失明效果。眼白、虹膜和瞳孔属于相应眼球的同一个可选对象，不额外叠加 HP。

### 伤害反应

使用框架 Protobuf 的 `DamageKind`，命中缺省时复用框架的存活部位等概率选点。普通八类伤害命中部位时，先对该部位记录输入 HP 损失，再按下表将同一损伤分配到该部位的局部账户。部位记录总体伤势，内部账户决定局部能力，两者不相加作为最终伤害或总体生命。

| 分类 | 皮肤 | 肌肉 | 骨骼 | 器官 | 即时反应侧重 |
|---|---|---|---|---|---|
| 钝击 `BLUNT` | 10% | 35% | 45% | 10% | 肌肉与骨组损伤较重 |
| 切割 `CUTTING` | 60% | 35% | 0% | 5% | 皮肤破坏与肌肉损伤 |
| 穿刺 `PIERCING` | 10% | 20% | 10% | 60% | 深层器官损伤 |
| 灼热 `HEAT` | 70% | 25% | 0% | 5% | 表面灼伤为主 |
| 寒冷 `COLD` | 40% | 45% | 5% | 10% | 皮肤及肌肉损伤 |
| 电击 `ELECTRIC` | 10% | 35% | 0% | 55% | 肌肉和器官损伤 |
| 腐蚀 `CORROSIVE` | 80% | 20% | 0% | 0% | 接触表层破坏 |
| 毒性 `TOXIC` | 0% | 20% | 0% | 80% | 器官损伤为主 |

以上是人体首轮可调整的游戏数值，保存在 `HumanDamage`。同类模块均分该层份额；某层不存在时，只在当地实际存在且配置了权重的其他层之间按比例重分配。例如手臂没有内脏，穿刺不会改去伤肺。每层按实际构型的所属部位与组织类型寻找，旧存档缺骨组时也不会伪造骨骼。已经归零的模块仍承担分额，过量部分裁剪，不形成额外穿透。

可信宿主精确指定组织或器官时直接扣该目标；`CUSTOM` 同样只扣选定账户，由具体附属继续定义特殊机制。伤害回执固定所有目标与剂量，重试不重新选点或分层。肌肉损伤影响框架计算的当前能力，器官归零影响既有加工可用性；骨折、流血、僵直、麻痹和持续中毒等独立伤势状态尚未实现。本次不把这些名称作为已经生效的状态返回。

### 动作与恢复

`HumanActions` 经 `HumanContent.bundle().actions` 登记以下定义，版本均为 1。运行实例存于框架身体，Human 不另存玩家动作状态。

| 动作 ID | 使用的组织 | 使用的器官 |
|---|---|---|
| `human:walk` | 左右臀大肌、股直肌、腓肠肌、趾短屈肌 | 无 |
| `human:run` | 同上述下肢肌肉 | 无 |
| `human:breathing` | 膈肌、注意组织 | 左右肺 |
| `human:open_meridian` | 注意组织 | 脑、左右肺 |

多动作可以并存；同一组织被任何动作使用就不自然恢复。动作声明只管理占用，实际力、功率和做功时间由框架做功命令及开脉时间执行器结算。Fabric 运动适配已识别真实行走/疾跑；内容库本身不检测 Minecraft 状态。

人体肌肉初始 `recovery_half_life_seconds = 30`，注意组织为 `20`，皮肤为 `0`（不自然恢复疲劳）。仅在未被使用时，疲劳按 `原疲劳 × exp(−ln(2) × 空闲秒数 / 半衰期)` 衰减。参数随实际构型保存，后续改造可修改；更新出生模板不会覆盖现有身体。

## 储存与开拓分别记录

肺经初始内腔容量为 50 体积，在 `ρ = 0.01` 时相当于 0.5 元；出生余额为 0.01 元、密度 `0.01`。显式固定 1 元批次新增 0.2 元；手动吐纳按环境浓度 × 每粒 1 格采样体积摄入，20% 炼化为密度 `0.01` 的无属性真元。同段可接收多颗，产物先存肺缓存，再遵守局部体积和预约规则入脉。未开拓时由自然扩散腾出局部空间。

肺经纳入后已自动向全身经脉自然扩散，未开脉可被动接收、存留和流动，因此首脉开拓前也能积累全身储量。每条经脉间连接配置被动吞吐 0.5 元/秒、最大批次 0.25 元、最小批次 0.0001 元；沿实际连接共享经脉总吞吐、容量与唯一账本。分支按连接 ID 稳定排序，参数与后续引导边界见[修炼要求](Cultivation.md)。

全身内腔初始容量为 2000 体积，按游离态密度显示相当于 20 元；这不代表出生时已有 20 元。实际存量仍按各账户逐条求和。普通主动运输入口要求源经脉已经开拓；专用开脉引导可调动未开脉余额，按规则承担独立费用与体积门槛。

## 游炁修炼与真炁准备门槛

游炁先开放基础上下肢主干：每侧肺、大肠两条手经与脾、胃两条足经，左右共八条，覆盖双臂和双腿。完成八条拓宽后，全身稳定内腔体积为 15000；游离态密度 `0.01` 时相当于 150 元。更高境界累计开放其他正经与奇经，天纹时展示当前完整的 36 条；局部支脉、络脉的独立模块属于后续细化，完整分层见[修炼要求](Cultivation.md)。未解锁经脉仍保存库存并参与被动流动，但不能主动拓宽。

| 项目 | 口径 |
|---|---|
| 出生实际储量 | 全身内腔共 0.36 元，不是容量上限 |
| 游炁初始稳定容量 | 全身经脉内腔合计 2000 体积；ρ=0.01 时显示为 20 元 |
| 修炼选择 | 当前境界已解锁经脉；游炁为左右各四条，共八条 |
| 游炁完成后的容量规划 | 全身稳定内腔容量合计 15000 体积；ρ=0.01 时显示为 150 元 |
| 突破判定 | 达到容量门槛后仍须完成增压、相变与持续适应等突破要求 |

体积容量由全身 2000 增至 15000，共增加 13000 体积。每条完成修炼后只增加目标经脉 1625 内腔体积，满足 `2000 + 8 × 1625 = 15000`。在密度 `0.01` 下，每条容量增量显示为 16.25 元；原有 50 体积经脉拓宽后为 1675 体积，原有 100 体积中轴经脉若被拓宽则为 1725 体积。密度不变，拓宽不会产生真元；外壁保持原容量。每条只计一次，重复启动或重连不重复获得体积。

容量成长与实际补气分别结算：修炼提高稳定体积上限，不凭空补满真元。外壁、器官缓存和在途货物不计入内腔体积门槛。突破所需实际储量、材料和外壁储备仍按独立突破条件检查，不能仅凭容量或临时灌入量自动改写境界。

开脉按当前稳定内腔体积检查：启动时全身内腔和目标脉分别至少占用 80%；维持时两者分别至少占用 60%。第 N 条连续维持 `10 + 5N` 秒，费用为 0.1 元/秒并从全身内腔按体积占比分摊；成功后目标脉永久增加 1625 体积。持续摄入与脑、精力成本见[游炁修炼与开脉要求](Cultivation.md)。

实现状态：出生模板采用本页初值；分层授权、开脉、连续适应与每脉一次永久扩容已接入权威运行。150 元只是密度 `0.01` 时的容量显示，不自动触发相变升境。开拓规则版本为 6；本轮不提供旧身体存档迁移，不能把旧元数容量字段直接解释为新体积字段。
