# 人体定义与初值

这些数值是基础内容的首轮游戏配置，不是生理测量结果，也不是主框架的默认值。定义位于 `server/src/main/java/dev/kizuna/meridian/human/server/HumanAnatomy.java`，全局身份、肺配方位于 `HumanContent.java`，出生规则位于 `HumanBirth.java`。

## 独立模块

| 模块 | 第一版内容 |
|---|---|
| 部位 | 17 个：头、颈、胸、腹、骨盆，加左右上臂、前臂、手、大腿、小腿、足 |
| 肌肉 | 19 块：左右胸大肌、肱二头肌、肱三头肌、肱桡肌、拇对掌肌、臀大肌、股直肌、腓肠肌、趾短屈肌，以及膈肌 |
| 皮肤 | 每部位一个独立皮肤模块，共 17 个 |
| 注意组织 | 头部 `attention_network`，用于手动引导的精力做功预算 |
| 器官 | 15 个：脑、左右眼、左右肺、心、肝、胆、脾、胃、小肠、大肠、左右肾、膀胱 |
| 经脉 | 十二正经各左右实例共 24 条，任督冲带各一条，阴阳跷和阴阳维各左右实例共 8 条；总计 36 条 |

这是用于起步的代表性组织集合，尚未枚举全部人体肌肉、骨骼、肌腱或关节。具名肌肉、皮肤、器官与经脉独立声明，通过部位 ID 关联，不把肌肉基础能力写进经脉。

正经在每侧形成明确的有向循环；奇经用双向连接交汇，任督连接提供中轴左右可达性。该图是中医经脉布局灵感下的游戏简化，不宣称完整解剖路径或医疗意义。端口只有输入、输出两个，运行仍服从框架连接、吞吐和在途预约规则。

实际聚气连接为 `left_lung.to.meridian`、`right_lung.to.meridian`，分别从对应肺的输出到同侧肺经输入。其他器官目前只有定义和端口，肌肉只有基础能力；它们的供元支路、专属配方和输出玩法后续补齐。

### 部位 HP

| 部位 | 最大 HP（左右各自） |
|---|---|
| 头 / 颈 / 胸 / 腹 / 骨盆 | 20 / 10 / 40 / 30 / 30 |
| 上臂 / 前臂 / 手 | 15 / 12 / 8 |
| 大腿 / 小腿 / 足 | 25 / 18 / 10 |

每块肌肉 HP 为 10、疲劳容量 100；皮肤 HP 为归属部位的 25%，主动能力为零。总体 HP 只汇总部位，不叠加肌肉和器官。此前讨论的整体 HP 低于 20% 或头部归零死亡，仍等待框架通用损伤与死亡条件契约，本包没有自行执行第二套死亡逻辑。

左右眼分别是 `left_eye` / `right_eye`，归属头部，每眼最大 HP 为 4，出生时各自满血。采用其他普通器官相同的 1 元缓存、1 元/秒吞吐及独立端口；当前没有视觉加工配方或失明效果。眼白、虹膜和瞳孔属于相应眼球的同一个可选对象，不额外叠加 HP。

### 动作与恢复

`HumanActions` 经 `HumanContent.bundle().actions` 登记以下定义，版本均为 1。运行实例存于框架身体，Human 不另存玩家动作状态。

| 动作 ID | 使用的组织 | 使用的器官 |
|---|---|---|
| `human:walk` | 左右臀大肌、股直肌、腓肠肌、趾短屈肌 | 无 |
| `human:run` | 同上述下肢肌肉 | 无 |
| `human:breathing` | 膈肌、注意组织 | 左右肺 |
| `human:open_meridian` | 注意组织 | 脑、左右肺 |

多动作可以并存；同一组织被任何动作使用就不自然恢复。动作声明只管理占用，实际力、功率和做功时间由框架做功命令及开脉时间执行器结算。Fabric 运动适配已识别真实行走/疾跑；内容库本身不检测 Minecraft 状态。

人体肌肉初始 `recovery_half_life_seconds = 30`，注意组织为 `20`，皮肤为 `0`（不自然恢复疲劳）。仅在未被使用时，疲劳按 `原疲劳 × exp(−ln(2) × 空闲秒数 / 半衰期)` 衰减。参数随实际构型保存，后续改造可修改；更新出生模板不会覆盖现有身体。

## 储存与开拓分别记录

第一版肺经局部容量 0.5 元、出生余额 0.01 元。显式固定 1 元批次新增 0.2 元；手动吐纳按环境浓度 × 每粒 1 格采样体积摄入，20% 炼化为无属性真元。同段可接收多颗，产物先存肺缓存，再遵守局部容量和预约规则入脉。未开拓时由自然扩散腾出局部空间。

肺经纳入后已自动向全身经脉自然扩散，未开脉可被动接收、存留和流动，因此首脉开拓前也能积累全身储量。每条经脉间连接配置被动吞吐 0.5 元/秒、最大批次 0.25 元、最小批次 0.0001 元；沿实际连接共享经脉总吞吐、容量与唯一账本。分支按连接 ID 稳定排序，参数与后续引导边界见[修炼要求](Cultivation.md)。

全身 20 元并非出生就能全部主动调用；“约十招”的全身预算需要开拓和可达性配套。普通主动运输入口要求源经脉已经开拓；专用开脉引导可调动未开脉余额，按规则承担独立费用与增压限制。

## 游炁修炼与真炁准备门槛

游炁先开放基础上下肢主干：每侧肺、大肠两条手经与脾、胃两条足经，左右共八条，覆盖双臂和双腿。完成八条拓宽后，全身稳定内腔容量达到 150 元。更高境界累计开放其他正经与奇经，天纹时展示当前完整的 36 条；局部支脉、络脉的独立模块属于后续细化，完整分层见[修炼要求](Cultivation.md)。未解锁经脉仍保存库存并参与被动流动，但不能主动拓宽。

| 项目 | 口径 |
|---|---|
| 出生实际储量 | 全身内腔共 0.36 元，不是容量上限 |
| 游炁初始常规容量 | 全身经脉内腔合计 20 元 |
| 修炼选择 | 当前境界已解锁经脉；游炁为左右各四条，共八条 |
| 游炁完成后的容量规划 | 全身稳定内腔容量合计 150 元 |
| 突破判定 | 达到容量门槛后仍须完成增压、相变与持续适应等突破要求 |

容量预算由全身初始 20 元增长至 150 元，共增加 130 元。每条完成修炼后增加 16.25 元稳定内腔容量，满足 `20 + 8 × 16.25 = 150`：原容量 0.5 元的经脉达到 16.75 元，原容量 1 元的经脉达到 17.25 元。每条只计一次，重复启动或重连不重复获得容量。

容量成长与实际补气分别结算：修炼提高承载上限，不凭空补满真元。外壁、器官缓存、在途货物和开脉期间的临时超压额度不计入这项稳定内腔容量门槛。突破所需实际储量、材料和外壁储备仍按独立突破条件检查，不能仅凭容量或临时灌入量自动改写境界。

开脉操作门槛独立于成长容量：目标脉自身至少 22 元，“已开脉＋目标脉”组合计从首条 22 元起，后续每条增加 `16.75 + n` 元，n 为此前已开条数；前两条分别为 22、39.75 元。80% 启动门槛、持续吐纳、脑耐力与精力消耗、完整公式及维持时间见[游炁修炼与开脉要求](Cultivation.md)。

实现状态：出生模板采用本页初值；分层授权、开脉、连续增压与每脉一次永久扩容已接入权威运行，150 元不自动触发相变升境。规则版本为 5，已有成长不重算，活动旧任务暂停后重新启动才采用新版上下肢分层；旧条件格式不自动迁移。已保存构型不会自动补入新脑耐力字段，旧身体须经显式内容迁移后使用对应规则。
